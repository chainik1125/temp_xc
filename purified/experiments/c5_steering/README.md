# C5 — RLHF / sentiment steering

Per-component orchestration for the steering case study from
T-SAE § 4.5 + Appendix B.2. See `docs/components/c5.md` for the
hypothesis, setup, and caveats.

## Files

- ``run.py`` — train + V7-tile-broadcast + Sonnet judge pipeline,
  one cell per `(arch, seed)`. Thin wrapper over
  ``temp_bench.runner.run_cell`` + ``SteeringCaseStudy``.
- ``analysis.py`` — leaderboard query → per-arch coh-vs-success
  curves with errorbars + AUTO-RESULTS markdown. Owned by
  ``temp_bench.report.render(component="c5")``.
- ``plots/`` — generated by analysis.py at render time.
- ``results.json`` — structured analysis output (auto-generated).

## Usage

```bash
# Full sweep (3 archs × 3 seeds; ~4 hr, ~$10 Sonnet):
TQDM_DISABLE=1 .venv/bin/python -m experiments.c5_steering.run

# Pre-test V7 on TXC-pro (fall back to PP if mean coh ≤ 1.0):
TQDM_DISABLE=1 .venv/bin/python -m experiments.c5_steering.run --pre-test-only

# Smoke test on the topk_sae baseline (cheap; uses --smoke flag,
# excluded from paper aggregates):
TQDM_DISABLE=1 .venv/bin/python -m experiments.c5_steering.run \
    --archs topk_sae --seeds 42 \
    --n-concepts 3 --strengths 1000 --n-steps 200 --smoke

# Render the AUTO-RESULTS block into docs/components/c5.md:
.venv/bin/python -c "from temp_bench import report; report.render(component='c5')"
```

## Key non-obvious choices

- **`eval_cfg["_workspace"]` is NOT used** — `runner.run_cell`
  re-hashes `eval_cfg` for the eval_key, so adding `_workspace` to
  it gives a different eval_key than what the runner ends up using
  for `metrics.json`. Workspace plumbing flows through a closure on
  the eval-fn instead.
- **The iterator is `temp_bench.data.nlp.batch_iter_from_act_cache`**,
  which yields `(B, seq_len, d_in)` full sequences. TXC archs do
  their own random-window extraction inside `train_step`; per-token
  archs flatten S into batch internally. One iterator works
  uniformly for both families.
- **`--n-steps` overrides `TrainingConfig.n_steps`** for fast smoke
  tests. Different `n_steps` → different `train_key` → fresh
  checkpoint, so the overridden cell never aliases to the full-sweep
  cell's HF artifact.
- **`--smoke` tags the leaderboard row** with `eval_cfg["smoke"] =
  True`. `analysis.py` filters those out so smoke cells don't
  pollute the paper-bound aggregates. Same convention as
  `agent_nlp`'s C3 smoke rows.
