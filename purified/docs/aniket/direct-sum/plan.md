## Direct-sum "which-process" benchmark — plan

**One-line:** superpose J independent generative processes in orthogonal
feature blocks of R^{d_in}; train a temporal SAE on the superposition; then
ask whether the SAE code can attribute each sequence to its generating
process. Because all J processes share the **same one-token emission
marginal** but differ in their **temporal dynamics**, no per-token or
order-invariant estimator can beat chance (1/J); only an order-sensitive
temporal architecture can.

This is Dmitry's 2026-06-01 request: *"which process" determination in
direct-sum processes.*

### Provenance

No prior direct-sum or which-process code exists anywhere in the repo (grep
confirms). The design below is new and grounded in the FreqBench framework
already established in `docs/components/freq_bench.md` and
`docs/aniket/freq-bench/theory.md`. It reuses the `freq_bench` evaluator
(experiment="freq_bench") and `FreqBenchData` dataclass unchanged.

### 1. Construction

#### 1.1 Processes and blocks

Partition R^{d_in} into J orthogonal subspaces ("blocks") of dimension
B = d_in / J each (require d_in divisible by J). Each process j ∈ {0,…,J-1}
lives in block j.

Within block j, allocate M = B feature directions via QR of a random
(B, B) Gaussian: these are the emission atoms for process j. Each token in
block j is a one-hot emission of one of M = B atoms (plus Gaussian noise σ).

#### 1.2 Dynamics: signed-velocity AC phase walks

Each process j drives a **phase ring Z_M** (M = B) at a **signed velocity**
v_j. The J processes use **different signed velocities**: a symmetric ladder

    v_j = sign_j × base_speed,   j = 0,…,J-1

where sign_j alternates (+ for even j, − for odd j) and base_speed is chosen
so that a W-token window reveals the velocity unambiguously from ordered
context:

    phase_j(t) = (φ0_j + v_j · t)  mod M

Critically, to enforce the **shared-marginal** property:
- Every process uses **the same speed magnitude** |v_j| = base_speed = 1.
- Only the sign of the velocity differs between process pairs.

For J > 2: use **two alternating signs** only (+ and −), and instead
distinguish additional processes by **phase-offset class within the same
velocity sign**, or more cleanly by setting different **base_speed values**
for different process groups. The simplest clean design for arbitrary J:

    v_j = +1   for j < J//2
    v_j = -1   for j ≥ J//2

Within each sign group the processes are further distinguished by their
block-feature assignment (entirely different emission atoms in different
blocks). The token-emission marginal of each process is uniform over M
phases — identical across all J processes — so a per-token probe sees the
same marginal distribution from every block and cannot attribute.

**Actually, simplest and cleanest design chosen (and implemented):**

Each process j uses velocity

    v_j = (+1)  if j % 2 == 0
    v_j = (-1)  if j % 2 == 1

and block j has its own independent QR-orthonormal set of M = d_in/J emission
directions. Since the phase walk is ergodic on Z_M with period M, the
marginal distribution of any single phase in block j is **uniform over M
atoms** regardless of j or v_j. Hence:

    E[x_t | process j, t] = 0   (unit-norm emissions with uniform phase → zero mean)
    Cov(x_t | process j, t) = (1/M) I_{B×B}   (same for all j)

The emission marginal is identical across all J processes in every block.

#### 1.3 Label semantics and "active process" design

**Exactly one process is designated "active" per sequence, driving the
block-local emission.** The other J-1 processes also emit (so the full
activation is the superposition of all J block emissions), but their block
emissions are drawn from the SAME phase-walk process with velocity v_j and an
INDEPENDENTLY sampled starting phase. The LABEL y ∈ {0,…,J-1} is the index
of the active process.

Wait — if all J blocks are always emitting with their own dynamics, the label
is undefined unless there is something distinguishing the "active" block.

**Revised (cleaner) semantics — chosen design:**

Each sequence is generated by EXACTLY ONE active process j. That process's
block emits with its full AC phase walk. The remaining J-1 blocks emit from a
**null/baseline** distribution — a static (DC) random phase, i.e. the same
random atom at every token within the sequence (i.e. velocity = 0). This
makes the DC blocks "noise" and only the AC block carries order information.

Now:
- Single-token probe of any block sees the same one-hot emission (uniform
  over M phases). All J blocks look identical token-by-token: A_loc = 1/J.
- Order-sensitive probe of the full sequence: only block j is AC (has
  transitions); the DC blocks have no transitions. The arch can identify
  which block is moving, so A_oracle = 1.

This is the cleanest separation: DC blocks vs AC active block. Per-token
probe cannot tell them apart (marginals match); temporal probe detects
which block has transitions.

**Shared-marginal check:**
- Active block (velocity v_j ≠ 0): phase walks, marginal = Uniform(M). ✓
- Null block (velocity 0, random constant phase): marginal = Uniform(M). ✓

Both are uniform over M atoms in each token. The marginals are identical. A
per-token frequency count of active block vs null block is identical in
expectation. An order-invariant probe (bag of tokens) cannot distinguish.

#### 1.4 Why per-token fails and temporal wins

A per-token probe sees x_t ∈ R^{d_in}. In block j' ≠ j (null blocks) the
emission is the same atom repeated W times. In block j (active) the emission
walks. But the ONE-TOKEN marginal is Uniform(M) in both cases, so the
expected feature at any single token is the zero vector in any block, and the
marginal distribution is identical.

Per-token probe accuracy = 1/J = chance.

An order-sensitive probe sees that block j has CHANGING atoms over time
(velocity ≠ 0) while all other blocks have CONSTANT atoms. This is
identifiable from any two adjacent tokens in block j: φ(t+1) − φ(t) ≡ v_j
(mod M) ≠ 0. With noise σ, the temporal arch needs enough sequence length W
to accumulate this evidence, but in principle A_oracle = 1.

The shuffle/reverse order controls diagnose this:
- A_shuffle → 1/J (shuffling destroys the AC signal; all blocks look DC).
- A_reverse: active block reverses velocity sign; arch trained for forward
  velocities gets a flipped signal → A_reverse < 1/J if the arch encodes
  the signed direction.

#### 1.5 Oracle

Given the full sequence with no noise (σ=0): check each block j' for
whether the phase sequence is consistent with velocity ≠ 0 vs velocity = 0.
The active block has φ(t+1) ≠ φ(t) for all t (with |v|=1); null blocks have
φ(t+1) = φ(t) for all t. So any two adjacent tokens identify the active block
exactly. A_oracle = 1.0.

With noise σ=0.1, the oracle is still 1.0 at the population level (the
correct process has the minimum sum-of-squared-differences from a constant).

### 5. Pre-registered predictions (as of 2026-06-01, before launch)

These are registered before any GPU run.

#### 5.1 NTPS predictions

| arch | J=4 (NTPS) | J=8 (NTPS) |
|---|---|---|
| `topk_sae` (per-token) | ≈ 0.00 | ≈ 0.00 |
| `txcdr_t5` (sliding T=5) | ≥ 0.50 | ≥ 0.40 |
| `txc_base_TW` (joint T=W) | 0.05–0.20 | 0.05–0.15 |
| `tfa` | ≥ 0.40 | ≥ 0.30 |

Rationale:
- `topk_sae` cannot use temporal order; stuck at A_loc = 1/J → NTPS ≈ 0.
- `txcdr_t5` sliding T=5 has position-mixing + sliding: strong AC signal
  detection; expected to dominate as in the AC bench.
- `txc_base_TW` joint T=W=16: has position-mixing but not sliding; limited
  SNR per the §3.6 theory; modest NTPS expected.
- `tfa` attention: mixes positions with attention, effectively sliding;
  should score near `txcdr_t5`.
- J=8 harder than J=4 because A_loc = 1/8 (larger oracle-to-local gap, more
  classes to distinguish), but same architecture capability.

#### 5.2 Order-control predictions (J=4)

| arch | A > 1/J | A_shuffle ≈ 1/J | A_reverse < 1/J |
|---|---|---|---|
| `topk_sae` | no | yes | no (≈ 1/J) |
| `txcdr_t5` | yes | yes | yes (signed direction) |
| `txc_base_TW` | marginal | yes | maybe |
| `tfa` | yes | yes | yes |

The reverse-below-chance signature is the diagnostic for signed-direction
encoding. For the which-process task, reversing the active block's velocity
from +1 to -1; an arch that encoded the direction of the active block will
get the attribution wrong in a predictable way (probe calibrated for forward
velocity now sees backward velocity).

#### 5.3 Key qualitative prediction

**Per-token (`topk_sae`) stays at A_loc = 1/J (chance) for ALL J.**
This is guaranteed by the shared-marginal construction: the one-token
marginal is uniform over M phases in every block, regardless of active vs
null, regardless of J. Any per-token probe trained on mean-pooled codes
will see statistically indistinguishable features. NTPS = 0.

If this fails (topk_sae gets NTPS > 0.05), the shared-marginal property has
been violated in the implementation — the null-block constant-phase emission
has a different marginal than the AC-block walking-phase emission, and a
per-token frequency count can cheat. Diagnosis: check that
E[x_null_t] ≈ E[x_active_t] ≈ 0, and
Cov(x_null_t) ≈ Cov(x_active_t). Fix: ensure null-block phase is UNIFORMLY
sampled per sequence (not a fixed phase) so the marginal is uniform.

### 7. Open questions for Dmitry (non-blocking)

1. Should the null blocks emit **pure noise** (no structured emission at all)
   rather than a constant-phase walk? Pure noise would also have a uniform
   marginal but might make the AC-block signal even more salient. The
   current constant-phase design is cleaner (still comes from the same ring
   emissions) and more controlled. Document and confirm.

2. For J > 2 where two processes share the same velocity sign (v_j = +1 for
   j=0 and j=2), could the arch confuse them? No — they live in completely
   different orthogonal blocks, so the block identity is unambiguous. But
   worth noting.

3. The construction is "attribution by AC presence" rather than "attribution
   by AC direction." A richer variant would have all J blocks AC (all
   velocities ≠ 0) and the label based on WHICH velocity. That would test
   multi-process filtering simultaneously. For the initial bench the current
   "one AC block vs J-1 DC blocks" is cleaner and has a sharper A_oracle = 1
   guarantee.
