## Hypothesis

On standard SAEBench-style sparse-probing tasks, TXC-pro matches the
best per-token SAE baseline at the matched-sparsity (k=5) regime and
delivers a small but seed-significant win at less-sparse regimes (k=20).
TXC-base (vanilla TopK + anti-dead) matches per-token SAE at every k.

## Caveats

- Phase 7 found `mlc` (cross-layer crosscoder, not temporal) ties or
  beats the temporal TXC at k=5. This is a **legitimate result** —
  one of two competitive structural inductive biases. Report MLC
  *if* the user agrees to scope it as related work / appendix.
- σ_seeds dominates the gap at k=5; the paper's k=5 claim must be
  "competitive with topk_sae", not "beats topk_sae".
- Phase 7 leaderboard numbers (`txc_bare_antidead_t5` k=20: 0.9127,
  k=5: 0.8683) are **BASE-side**. Re-running on IT may shift those
  numbers — Phase 7 noted "the IT side is entirely missing" so we
  do not yet have IT probing AUC for our locked archs. **Plan to
  reproduce the Phase 5 leaderboard on IT first** (we already have
  Phase 5's IT-side numbers as ground truth) and then benchmark
  TXC-base / TXC-pro against them.
- Caching is the long pole — start it as soon as Agent NLP is
  provisioned.

### Switching subject model or layer

The framework caches at three levels:
1. activation cache keyed by `(subject_model, layer, dataset, n_seqs, seq_len)`
2. trained-model cache keyed by `(arch, arch_version, hparams, seed, train_data_key)`
3. eval-result cache keyed by `(train_key, eval_protocol_version, eval_cfg)`

Switching `subject_model: gemma-2-2b-it → gemma-2-2b` invalidates only
(1) and the downstream re-evaluations; arch implementations and code
versions are untouched. This is by design so we can run a "BASE-side
extension" experiment after the IT-side is locked, without touching the
core paper claims.
