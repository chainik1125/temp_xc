How Nura's Feature-Resolved Attention (FRA) pipeline works, end-to-end, and how we wrap it for the Phase 1 reproduction + Phase 3 same-budget SAE benchmark. Repos: fra_proj (Nura's framework, branch dmitry-em-repl) and temp_xc (planning + analysis, same branch name).

1. Single-prompt FRA forward pass

Given one prompt, the model is run once with a SAE attached at blocks.24.ln1.hook_normalized. The SAE encodes pre-attention activations into 102 400 features (TopK k = 64); those features are then projected through the attention head's weight matrices to compute per-feature contributions to QK (attention pattern) and OV (value path).

Step 1 — one prompt, one forward pass, two sparse tensors. Repeat for all 8 EM eval prompts and accumulate.

2. Multi-prompt feature ranking

The QK and OV sparse tensors are accumulated across all 8 EM eval prompts to find features that consistently dominate (rather than being prompt-specific). Per fra/em_evaluation.py:rank_features_multi_prompt(): 

for prompt in EM_EVAL_PROMPTS:
    qk_pairs = rank_feature_pairs(compute_fra_sparse(model, sae, prompt))   # top-50 (λ, μ) pairs
    ov_feats = rank_ov_features(compute_ov_sparse(model, sae, prompt))      # top features by ‖W_dec W_V W_O‖

    qk_pair_scores[(λ,μ)] += sum_of_attribution
    ov_feat_scores[λ]     += sum_of_attribution

return {"qk": top_unique_features(qk_pair_scores), "ov": top_features(ov_feat_scores)}

This produces two ranked feature lists per attention head (we focus on H38 by default, with H0/H36/H7 as alternates per Nura's CODEBASE.md).

4. The headline metric

Δalign | coh ≥ 70 = max(mean_alignment) − min(mean_alignment) over α-sweep points whose mean coherence ≥ 70.

Captures the maximal alignment swing achievable while the model still produces coherent text. Computed by scripts/plot_c6_em_align_coh_grid.py:headline_metrics() in temp_xc — we re-use that exact definition in fra_proj/scripts/post_phase1_analyze.py so cross-project numbers are directly comparable.

A large Δ at coh ≥ 70 means: "we can move alignment a lot without breaking the model." That's the trade-off frontier the QK/OV intervention is optimizing.

5. The full multi-seed run (Phase 1)

run_experiments.py --task frontier_multiseed --em-model {medical|finance|sports} drives the full grid: 

3 seeds   ×   8 EM eval prompts   ×   6 α values   ×   3 conditions   =  432 generations
                                                                            per EM model

We run one frontier_multiseed call per EM domain in parallel. The four jobs (medical + random_baseline-medical + finance + sports) are pinned to the 4 H100 GPUs across two RunPods.

6. Phase 1 gate → branch

Pass: medical QK→OV Δalign|coh≥70 within ±5 of Nura v1

Run scripts/launch_phase3_saes.sh GO=1 — trains 4 same-budget SAEs in parallel:

  • pod 1 GPU 0 → blocks.24.hook_resid_pre
  • pod 1 GPU 1 → blocks.24.hook_resid_mid
  • pod 2 GPU 0 → blocks.24.hook_resid_post
  • pod 2 GPU 1 → blocks.25.ln1.hook_normalized

Each SAE: d_sae=102 400, k=64 (matches Nura), 100M tokens, ~1–2 hr/SAE on H100.

Push checkpoints (incl. intermediates) to HF under phase3_benchmark/sae/<hookpoint>/.

Fail: gap > ±5 from Nura v1

Stop everything Phase-3-bound. Fill in phase1_diagnostic.md ordered most-likely-root-cause first:

  • model-load divergence (LoRA revision / merge order)
  • SAE-load divergence (revision pinning)
  • GQA mapping (head 38 → kv_head 7?)
  • RMSNorm / RoPE convention
  • judge variance (re-judge with Claude)
  • prompt drift
  • α-sweep no-op at α=1.0
  • seed handling
